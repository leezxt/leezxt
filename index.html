關於我 / About

過去主要從事服務業，累積了與人溝通、理解需求及處理現場問題的經驗。一次轉職學習的機會，讓我接觸到 AI 與後端開發，也意外發現自己對「把想法做成產品」充滿興趣。

我運用 Java、Spring Boot 與 AI 工具，獨立開發台股分析系統及端對端加密通訊軟體。服務業讓我學會站在使用者角度思考；程式開發則讓我能真正動手解決問題。現在希望成為一名懂使用者、能耐心除錯，也能善用 AI 完成產品原型的 AI 應用工程師。

自傳 / Autobiography

我原本就讀財經法律，畢業後在宜蘭工作。隨著工作經驗累積，我發現當地職涯選擇與薪資成長空間有限，因此開始思考轉換跑道。剛好接觸到 AI 與後端工程師課程，第一次把需求拆成資料結構、程式邏輯與 API，再看見功能實際運作，讓我確定自己願意長期投入軟體開發。雖然目前沒有軟體業的正式工作經歷，但我選擇持續開發完整專案，將學習內容轉化為能操作、能測試、也能持續改進的成果。

課程中的專案皆由我個人完成。4 月因個人投資與分析需求開始構思股票系統，並在 5 月完成 Stock AI System 畢業專案。系統使用 PostgreSQL／pgvector，串接 Yahoo Finance、TWSE、FinMind、Alpha Vantage、FMP、MOPS 等金融資料來源與 AI Provider，實作市場搜尋、技術摘要、AI 分析、模型比較、聊天、回測及 RAG 文件檢索。6 月完成的 NewIdeaCase 則依老師教授內容延伸設計，以 Java／Spring Boot 建立模組化後端，整合 MongoDB、Redis、OIDC／JWT、多租戶權限、Docker 與 RAG。這兩個畢業專案讓我第一次把後端、外部 API、資料庫與生成式 AI 放進同一套完整流程，也讓我理解功能完成只是起點，資料一致性、安全邊界、例外處理與部署方式同樣重要。

課程結束後，我沒有停在畢業專案，而是繼續依照自己的投資需求開發 StockPredictor，讓它從台股查詢工具逐步擴充為整合歷史行情、K 線、技術指標、法人籌碼、基本面、ETF 折溢價、市場廣度、雷達評分與批次掃描的系統。系統透過 FinMind、TWSE／TPEx 與 Yahoo Finance 取得資料，使用 client、排程與背景回補流程，再將不同 API 的欄位、日期範圍、空值與錯誤格式轉換為一致的內部模型。當來源暫時無法使用時，也需要設計 fallback 與可理解的錯誤回應。這段經驗讓我體會到，串接 API 不只是成功取得 JSON，而是要讓來源差異與失敗情境不影響後續分析。

StockPredictor 早期使用 H2，原本設計了兩週回測機制，但重新開啟軟體後缺少可延續的歷史資料，因此難以觀察投資策略的實際效果。我將主要資料庫遷移至 PostgreSQL 17，加入 Flyway、HikariCP、repository 分層、Testcontainers 與 Docker Compose。遷移最麻煩的是測試流程與時間，需要反覆確認資料寫入、查詢、回補、回測與既有功能是否仍然一致。完成後，資料可以持續保存並支援後續比較，也讓我理解真實系統不只需要新增功能，還要考慮資料遷移、相容性、備份、回復策略，以及每次重構是否能被驗證。

目前最想持續投入的是 Secure Messenger。市面上的通訊軟體常加入許多我不需要的功能，因此我希望把通訊簡化，聚焦聯絡人、信任關係與安全傳訊。系統結合 Flutter、Java／Spring Boot、WebRTC、WebSocket、JWT 與 PostgreSQL，從註冊、邀請碼與公鑰信任開始，逐步加入端對端加密訊息、離線信箱、ACK／重試、已讀狀態與推播。最初訊息必須手動按下同步按鍵才能更新，後來我把流程改成依待機秒數自動同步，目前已能在兩台 Android 模擬器之間成功傳送訊息。這個里程碑讓我更理解，產品原型不只要功能存在，也要讓操作流程接近使用者真正期待的體驗；通訊系統的可靠性，也必須從網路中斷、訊息重送與狀態同步等失敗情境來驗證。

上述專案大多透過 AI 協作完成。我目前以 Codex 為主要開發工具，DeepSeek 作為輔助驗證與除錯，從需求拆解、開發到測試都會運用 AI。我負責提出產品需求、準備硬體與執行環境、確認功能是否符合預期，並針對不一致的結果提出修改方向。我會在提示詞中交代目標、現有架構、限制與驗收條件，把大型功能拆成可以逐項完成的步驟，再檢查程式、設定、日誌與實際操作結果。遇到問題時，我不直接接受生成答案，而是觀察 AI 的分析流程、理解原因後再自行驗證。每天投入約三至五小時，通常以一至兩週完成一個可操作的原型；Secure Messenger 也讓我確認自己能運用 AI 工具，將一個想法從零推進到可測試的產品。

我的目標是成為能獨立完成產品原型的 AI 應用工程師，投入生成式 AI／RAG 系統整合、AI 應用開發，或結合 Java 後端的 AI 相關職務。我希望把 API 串接、資料庫、容器化、跨平台與 AI 協作經驗帶入團隊，並持續補強系統設計、測試、資安與部署能力。對我而言，AI 不只是加快寫程式的工具，而是協助我釐清需求、理解系統、驗證流程並把構想穩定落地的方法。

Featured Backend Platform

NewIdeaCase / 模組化後端與 RAG 平台

使用 Java 21、Spring Boot 4.1 建置模組化單體平台，完成商品目錄、使用者資料與訂單流程；支援 Redis read-through cache、游標分頁、部分更新、樂觀鎖與一致的 RFC Problem Details 錯誤契約。

整合 Spring Security、OIDC／JWT 與 Keycloak，由後端解析 tenant、role 及 route scope；RAG 流程實作具 ACL 過濾的文件匯入、可靠切片、Ollama Embedding／生成與來源引用，避免跨租戶資料洩漏。

以 Docker Compose 建立 MongoDB replica set、Redis、Caddy、Prometheus、Grafana、Loki、Alertmanager、Mailpit 與 Portainer，並開發 ECharts 營運監控 Dashboard；使用 JUnit 5、Testcontainers 及驗收腳本覆蓋 API、資料與平台服務。

目前範圍：本機平台與 RAG adapter 已實作；AWS SDK、正式 AWS 部署及 MongoDB Atlas Vector Search 仍保留為後續整合邊界。

Cross-platform Project

Secure Messenger / 端對端加密即時通訊系統

以 Flutter 與 Java 21／Spring Boot 4.1 開發模組化 P2P 通訊系統；已用兩台 Android AVD 驗證註冊、邀請碼、雙向聯絡人、公鑰信任及一對一端對端加密文字訊息。

以 WebRTC DataChannel 傳輸加密訊息、WebSocket 進行 Signaling，並完成 P2P 失敗後的加密 Offline Mailbox fallback、ACK／重試及 STORED → DELIVERED → READ 已讀流程；後端使用 PostgreSQL、Flyway、JWT 與 Docker Compose。

已完成低頻 Presence 與 FCM HTTP v1 worker，並建立 GitHub Actions 與 Firebase Test Lab dry-run Gate；架構同時限制背景 heartbeat，以降低行動裝置資源消耗。

目前狀態：仍為內部 Android Alpha；雙真機、真實 FCM Push、正式簽章、Desktop 資源驗收與 iOS 實機 Gate 尚未完成。
